# 第 11 课：给数据插件绑定样式、简介和预览图

[上一课](10-自定义数据.md) · [下一课](12-天气屏幕进阶教程.md) · [返回总目录](../README.md)

上一课完成了最小自定义数据插件。这一课继续制作“演示传感器2”，把数据采集、屏幕样式、HTML 简介和 PNG 预览图放进同一个插件。导入一次插件后，用户既能测试数据，也能查看说明和同步配套样式。

本课完整示例位于 [`example/code/custom_data_plugin_demo2`](code/custom_data_plugin_demo2)：

```text
custom_data_plugin_demo2/
├── plugin.json
├── main.py
├── style_demo_sensor2.py
├── demo_sensor2_detail.html
└── preview.png
```

## 第一步：声明三个绑定资源

在 `plugin.json` 中同时开启三个绑定开关，并填写插件根目录内的文件名：

```json
{
  "protocol": 1,
  "key": "demo_sensor2",
  "name": "demo_sensor2",
  "zh_name": "演示传感器2",
  "interval": 5,
  "entry": "main.py",
  "bind_style": true,
  "style": "style_demo_sensor2.py",
  "bind_detail": true,
  "detail": "demo_sensor2_detail.html",
  "bind_preview": true,
  "preview": "preview.png"
}
```

三个开关彼此独立。某个开关为 `true` 时，对应字段和文件都必须存在，否则 Monitor 会拒绝加载插件。

| 开关 | 文件要求 | 导入后的用途 |
| --- | --- | --- |
| `bind_style` | `style_demo_sensor2.py`，无 BOM UTF-8，最大 16 KB | 在自定义数据页执行“同步样式” |
| `bind_detail` | `demo_sensor2_detail.html`，无 BOM UTF-8，最大 1 MB | 在受限页面中查看插件和样式说明 |
| `bind_preview` | `preview.png`，最大 5 MB | 在插件卡片中展示样式缩略图 |

样式、简介和预览图都必须直接放在插件根目录，字段中不能填写子目录或绝对路径。

## 第二步：产生样式需要的数据

`main.py` 的 `collect(config_json)` 返回以下结构：

```json
{
  "temperature_c": 26.4,
  "humidity": 55.0,
  "status": "ok",
  "updated_at": "14:32:08"
}
```

Monitor 会把它放到 `snapshot.ext.demo_sensor2`。示例允许在设置面板中修改基础温度和基础湿度，再围绕基准值生成轻微波动。温度达到 30℃ 时，`status` 会变为 `warning`，便于观察样式的告警颜色。

## 第三步：让绑定样式读取插件数据

绑定样式与普通自定义样式遵循相同规范。示例中的关键读取逻辑是：

```python
@staticmethod
def _read_sensor(snapshot):
    """从 snapshot.ext.demo_sensor2 中读取传感器对象。"""
    return (snapshot or {}).get("ext", {}).get("demo_sensor2", {}) or {}
```

始终使用 `.get()` 并提供空对象兜底。插件第一次采集尚未完成、被停用或执行失败时，样式仍应正常绘制等待提示，不能因为字段不存在而中断屏幕刷新。

示例把主体声明为一个脏区域。只有 `demo_sensor2` 数据发生变化时才刷新温度、湿度进度条、状态和更新时间：

```python
@classmethod
def select_dirty_regions(cls, previous, current):
    """当演示传感器2数据发生变化时选择主体区域。"""
    previous_data = (previous or {}).get("ext", {}).get("demo_sensor2", {})
    current_data = (current or {}).get("ext", {}).get("demo_sensor2", {})
    return cls.create_dirty_regions() if previous_data != current_data else []
```

## 第四步：编写简介和准备预览图

HTML 简介适合解释数据来源、字段意义、告警条件和使用步骤。不要在简介中依赖脚本、外部页面或本机文件；它会在受限 `iframe` 中显示。

预览图应尽量反映样式的真实布局。推荐使用与屏幕相同的宽高比，本例提供 `480 × 640` PNG，对应默认竖屏的 `240 × 320` 比例。预览图只是说明资源，不会上传到 Pico。

## 第五步：导入并验证

1. 打开 OmniWatch 的“自定义数据”页面。
2. 单击“导入目录”，选择 `custom_data_plugin_demo2`；分发时也可以先压缩成 ZIP。
3. 单击“测试”，确认返回值中包含温度、湿度、状态和更新时间。
4. 单击“查看简介”，确认 HTML 内容可以正常显示。
5. 检查插件卡片中的预览缩略图。
6. 单击“同步样式”，把“演示传感器2”样式上传到设备。
7. 在设备上切换到该样式，观察数值和状态随采集结果变化。

## 常见错误

| 提示或现象 | 检查内容 |
| --- | --- |
| 绑定样式文件不存在 | `style` 是否与根目录文件名完全一致 |
| 文件名必须为 `style_demo_sensor2.py` | 样式类的 `name` 是否为 `demo_sensor2` |
| 插件简介无法读取 | HTML 是否保存为无 BOM UTF-8 |
| 预览图格式不支持 | 扩展名和真实文件头是否都是受支持的图片格式 |
| 屏幕一直显示等待数据 | 插件是否启用、测试是否成功、样式读取的 `ext` key 是否为 `demo_sensor2` |

完成这一课后，可以用同一结构打包真实的温湿度传感器、NAS 状态或家庭自动化数据。下一课会把这种“采集插件加显示样式”的组合用于真实天气接口。
