# 第 10 课：自定义数据插件

[上一课](09-Dev模式.md) · [下一课](11-绑定资源插件.md) · [返回总目录](../README.md)

自定义数据插件运行在电脑端 Monitor 中，可把传感器、HTTP 接口、数据库查询或本地状态加入发送给 Pico 的 `snapshot.ext`。新版插件支持第三方 Python 库，并使用独立虚拟环境和独立子进程运行，不会与 Monitor 或其他插件的依赖版本互相影响。

## 插件目录结构

推荐把每个插件制作成一个目录：

```text
weather/
├── plugin.json
├── main.py
├── requirements.txt
├── style_weather.py       # 可选：绑定的屏幕样式
├── weather_detail.html    # 可选：样式简介
└── preview.png            # 可选：样式预览图
```

三个文件的作用如下：

| 文件 | 是否必需 | 作用 |
| --- | --- | --- |
| `plugin.json` | 是 | 声明插件名称、数据 key、配置面板和绑定资源 |
| `main.py` | 是 | 实现 `collect(config_json)` 采集方法 |
| `requirements.txt` | 否 | 声明需要由 Monitor 安装的第三方库 |
| `style_*.py` | 否 | 与数据插件一起分发的自定义屏幕样式 |
| `*.html` | 否 | 绑定样式的 UTF-8 简介页，最大 1 MB |
| `*.png` | 否 | 绑定样式的预览图，也支持 JPEG、GIF、WebP，最大 5 MB |

插件可以直接加载目录，也可以把目录压缩成 ZIP 后分发。ZIP 内允许再套一层同名目录，但整个压缩包必须且只能包含一个 `plugin.json`。

## 编写 plugin.json

```json
{
  "protocol": 1,
  "key": "weather",
  "name": "weather",
  "zh_name": "天气数据",
  "interval": 300,
  "config_panel": [
    {
      "name": "latitude",
      "zh_name": "纬度",
      "key": "latitude",
      "type": "number",
      "default": 39.9,
      "min": -90,
      "max": 90,
      "decimal": 4
    },
    {
      "name": "api_url",
      "zh_name": "天气接口",
      "key": "api_url",
      "type": "string",
      "default": "https://example.com/api/weather",
      "required": true,
      "reg": "^https://"
    }
  ],
  "entry": "main.py",
  "bind_style": true,
  "style": "style_weather.py",
  "bind_detail": true,
  "detail": "weather_detail.html",
  "bind_preview": true,
  "preview": "preview.png"
}
```

字段说明：

| 字段 | 作用 |
| --- | --- |
| `protocol` | 插件协议版本；`1` 兼容基础字段，`2` 支持动作和卸载钩子 |
| `key` | 写入 `snapshot.ext` 下的字段名 |
| `name` | 采集任务英文标识，完整任务 key 为 `custom_data.<name>` |
| `zh_name` | Windows 配置页和日志显示的中文名称 |
| `interval` | 默认采集间隔，单位为秒 |
| `config_panel` | 自定义配置项数组；省略时面板仍会自动包含 `interval` |
| `actions` | 协议 2 的插件动作白名单，键为稳定动作标识 |
| `uninstall` | 协议 2 可选布尔值；为 `true` 时删除前调用 `uninstall(context)` |
| `entry` | 插件入口文件，默认是 `main.py`，只能位于插件根目录 |
| `bind_style` / `style` | 是否绑定样式，以及根目录内的 Python 样式文件 |
| `bind_detail` / `detail` | 是否绑定简介，以及根目录内的 HTML 文件 |
| `bind_preview` / `preview` | 是否绑定预览图，以及根目录内的图片文件 |

`key` 和 `name` 只能包含英文字母、数字和下划线，不能以数字开头，最长 64 个字符，并且必须在所有插件中唯一。

### config_panel 字段

`interval` 是 Monitor 保留字段，不要在 `config_panel` 重复声明。每个配置项必须有唯一 `key`，支持以下类型：

| `type` | 界面控件 | 常用扩展字段 |
| --- | --- | --- |
| `number` | 数字输入 | `default`、`min`、`max`、`decimal` |
| `string` | 单行文本 | `default`、`required`、`min`、`max`、`reg` |
| `password` | 密码输入 | 与 `string` 相同，界面默认隐藏内容 |
| `textarea` | 多行文本 | 与 `string` 相同 |
| `boolean` | 开关 | `default` |
| `select` | 下拉选择 | `default`、非空 `options` |

`decimal` 是 0 至 12 的整数，可以在 JSON 中写成 `0` 或 `"0"`。`reg` 是对完整文本进行匹配的正则表达式。`select.options` 可以是简单值数组，也可以使用 `{"label": "显示名", "value": "value"}` 对象。

字段元素可以显式声明 `"kind": "field"`；省略 `kind` 时仍按字段处理。只读回填字段可增加 `"readonly": true`。

### Monitor 启用开关

插件是否启用由 Monitor 独立管理，不是 `config_panel` 配置项。启用状态保存在
`custom_data_enabled`，不会传入 `collect(config_json)`，插件也不能通过动作修改它。
停用会注销采集任务并停止插件进程，但保留插件配置和独立环境。新导入插件默认停用；
从旧版本升级时，原有插件默认保持启用。

### 配置动作与自动回填

协议 2 可以在面板中声明动作按钮。例如检测某个应用的安装目录：

```json
{
  "kind": "action",
  "action": "detect_application",
  "zh_name": "自动检测安装目录",
  "loading_text": "正在检测……"
}
```

动作必须同时在顶层白名单声明：

```json
{
  "actions": {
    "detect_application": {
      "method": "detect_application",
      "timeout": 10,
      "config_keys": ["application_path"]
    }
  }
}
```

入口方法接收包含当前配置快照的上下文，并返回配置补丁：

```python
def detect_application(context):
    """检测应用目录并回填已授权配置字段。"""
    return {
        "message": "检测成功",
        "config_patch": {
            "application_path": find_application_path(context["config"]),
        },
    }
```

Monitor 只接受 `config_keys` 明确授权的补丁字段，并再次执行类型与范围校验。补丁仅
回填当前表单，点击“保存配置”后才持久化生效。插件不能回填 `interval`、启用状态、
其他插件配置或任意 Monitor 设置。

### 删除前清理插件数据

插件若在自身目录之外创建缓存或数据库，可以在清单声明：

```json
{
  "protocol": 2,
  "uninstall": true
}
```

并在入口实现：

```python
def uninstall(context):
    """清理由当前插件明确拥有的数据。"""
    cleanup_owned_data(context["config"])
    return {"message": "清理完成"}
```

删除时 Monitor 会先调用钩子，成功后才删除插件目录和独立环境。钩子异常或超时会
中止删除并保留现场，便于修复后重试。卸载代码必须校验精确目标，严禁删除用户目录、
磁盘根目录或整个 Monitor 数据目录。覆盖安装属于升级，不执行 `uninstall`。

### 绑定样式、简介和预览图

样式、HTML 和预览图与插件一起保存在插件根目录，Monitor 直接从该目录建立资源索引，不会再复制一份到其他目录。这样覆盖、更新或删除插件时，代码与展示资源不会出现版本不一致。

开启绑定时，对应文件必须存在：

- 样式文件应遵循 `style_<样式名>.py` 规范，并通过 OmniWatch 样式校验。
- HTML 必须使用无 BOM UTF-8，不超过 1 MB，将在受限 `iframe` 中展示。
- 预览图支持 PNG、JPEG、GIF 和 WebP，不超过 5 MB，Monitor 会同时校验扩展名和文件头。
- 自定义数据页会显示预览缩略图、“查看简介”和“同步样式”操作。

下一课将通过完整的[演示传感器2插件](code/custom_data_plugin_demo2)，逐步讲解如何同时绑定样式、简介和预览图。

## 编写 main.py

```python
#!/usr/bin/env python3
"""采集天气接口数据。"""

import requests
import json


def collect(config_json):
    """解析 Monitor 面板配置，请求天气接口并返回可序列化数据。"""
    config = json.loads(config_json)
    response = requests.get(config["api_url"], timeout=10)
    response.raise_for_status()
    payload = response.json()
    return {
        "temperature_c": payload.get("temperature_c"),
        "status": payload.get("status", "unknown"),
    }
```

入口模块推荐定义 `collect(config_json)`。Monitor 会将当前插件面板的所有值（包括 `interval`）编码为 JSON 字符串传入，插件使用 `json.loads(config_json)` 解析。旧版无参数 `collect()` 仍然兼容，但无法读取自定义面板值。

返回值必须能够转换成 JSON，例如 `dict`、`list`、字符串、数字、布尔值或 `None`。不要返回文件句柄、数据库连接、对象实例和字节流。

Monitor 会在插件自己的 Python 子进程中执行 `collect()`。默认超过 10 秒仍未结束时会终止子进程，因此网络和数据库调用也应设置更短的超时时间。

## 声明第三方依赖

在 `requirements.txt` 中按标准 pip 格式声明依赖，推荐锁定版本：

```text
requests==2.32.3
```

每个插件都有自己的虚拟环境：

```text
%LOCALAPPDATA%\PicoMonitor\pluginEnvs\weather\
```

插件 A 使用 `requests==2.31.0`、插件 B 使用 `requests==2.32.3` 时不会冲突。修改 `requirements.txt` 后，管理窗口会把状态重新显示为“依赖未安装”，再次单击“安装依赖”即可更新。

依赖来自 pip 软件源。安装第三方包前请确认包名、版本和来源可信；依赖安装脚本与插件代码都具有当前 Monitor 用户能够访问的系统权限。

## Windows 加载和安装

1. 右键 OmniWatch 托盘图标，打开“自定义数据”。
2. 单击“导入 ZIP”选择 ZIP 插件包；开发时也可单击“导入目录”。
3. 找到刚导入的插件，单击“安装环境”。
4. 等待底部日志显示“安装完成：环境就绪”。
5. 单击“测试”，确认能够看到 JSON 结果。
6. 打开“设置”，在插件自己的独立面板中设置采集间隔和其他配置项。
7. 保存配置；面板值和采集间隔会立即热更新，无需重启 Monitor。

Windows 安装包已经携带专用于插件的完整 Python Runtime，不需要用户另外安装 Python。Runtime 位于 OmniWatch 安装目录的 `plugin-runtime`，每个插件的虚拟环境基于它创建。

## 制作 ZIP 插件包

在 `weather` 目录的上一级执行：

```powershell
Compress-Archive -Path weather -DestinationPath weather.zip
```

不要把 `.venv`、缓存、密码文件或开发机配置放进 ZIP。Monitor 会拒绝包含路径穿越或符号链接的压缩包，也不会直接在压缩包内执行代码。

## Linux 使用

Linux 同样使用插件目录和独立虚拟环境。系统需提供 `venv` 和 `pip`：

```bash
sudo apt install python3-venv python3-pip
```

把插件目录复制到运行 Monitor 的用户数据目录后重启服务。以默认 root 服务运行时，目录通常是：

```text
/root/PicoMonitor/customData/
```

当前 Linux 服务没有图形化依赖安装窗口，可使用对应 Python 创建环境并安装依赖：

```bash
python3 -m venv /root/PicoMonitor/pluginEnvs/weather
/root/PicoMonitor/pluginEnvs/weather/bin/python -m pip install -r /root/PicoMonitor/customData/weather/requirements.txt
```

然后在 `/etc/pico-monitor.conf` 设置插件面板值：

```yaml
custom_data:
  configs:
    weather:
      interval: 300
      latitude: 39.9
      api_url: https://example.com/api/weather
```

保存后执行：

```bash
sudo systemctl restart pico-monitor
```

## 在样式中读取数据

插件 `key` 为 `weather` 时，结果会合并到：

```python
{
    "ext": {
        "weather": {
            "temperature_c": 27.3,
            "status": "ok"
        }
    }
}
```

样式应始终使用 `.get()` 读取：

```python
ext = snapshot.get("ext", {})
weather = ext.get("weather", {})
temperature = weather.get("temperature_c")
status = weather.get("status", "unknown")
```

首次采集尚未完成、插件超时或执行失败时，对应字段可能暂时不存在。

## 常见错误

| 提示或现象 | 原因 | 处理方法 |
| --- | --- | --- |
| `环境未安装` | 尚未创建插件虚拟环境 | 选中插件并单击“安装依赖” |
| `依赖未安装` | requirements 首次加载或已经修改 | 再次单击“安装依赖” |
| `plugin.json 读取失败` | JSON 格式错误或编码异常 | 使用无 BOM UTF-8 并检查 JSON 语法 |
| `CUSTOM_DATA_NAME 重复` | 两个插件使用同一个任务名 | 修改其中一个插件的 `name` |
| `CUSTOM_DATA_KEY 重复` | 两个插件写入同一个 `ext` 字段 | 修改其中一个插件的 `key` |
| `collect 执行超过 10 秒` | 网络请求、数据库或代码阻塞 | 为外部调用设置超时并缩短单次工作量 |
| `插件子进程执行失败` | 导入失败或 collect 抛出异常 | 查看窗口底部的完整 Python 异常 |
| 选择单个 `.py` 文件无法导入 | 单文件插件格式已停止支持 | 创建含 `plugin.json` 和入口文件的标准插件目录，再加载目录或打包为 ZIP |
| pip 安装失败 | 包名、版本、网络或编译环境有问题 | 检查安装日志，优先使用提供 Windows wheel 的版本 |

建议一个插件只负责一种数据来源。天气、NAS 状态和家庭传感器分别打包，便于独立升级依赖、配置间隔和定位错误。
